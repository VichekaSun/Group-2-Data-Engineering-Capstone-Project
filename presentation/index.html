Configuration and the Snowflake connection

Lim Viboth
.env: one file, never committed
GroupVariables
AirflowAIRFLOW_IMAGE_NAME, AIRFLOW_UID
MySQLMYSQL_HOST, PORT, USER, PASSWORD, DATABASE
SnowflakeSNOWFLAKE_ACCOUNT, USER, PASSWORD, WAREHOUSE, DATABASE, ROLE

Secrets stay out of git

.env.example holds only the names; .gitignore keeps .env out of the repo. Compose passes the values to the Airflow container.

The Snowflake side

Defaults apply only when a variable is missing; real values come from .env. Governance proposes a dedicated loader role instead of SYSADMIN.

03 · Methodology

Governance and privacy

Sun Vicheka

In docs/governance.md every policy line carries a tag: Enforced the code or config does it, Agreed in the roadmap, Proposed still needs team agreement.

Ownership

Clear owners

Each data asset has an owner: data and quality (Chea Dalin), warehouse and infrastructure (Lim Viboth), reports and documents (Sun Vicheka).

Lineage

Traceable path

source → raw → clean / rejects / logs → quality report → ANALYTICS → Power BI.

Retention

Raw kept per run

Raw copies are never overwritten; warehouse data kept 5 years (agreed).

Privacy

No personal data

Synthetic data only; no names, phones, emails or addresses; reports stop at employee_id.

Definitions

One meaning per KPI

Headcount, attendance rate and approved performance are defined once in the README and governance doc.

Change

Pull requests

Branch, open a pull request, get a review, merge. Docs change in the same PR as the code.

Source: docs/governance.md, docs/data_dictionary.md.

What we would do next

Sun Vicheka
What worked

Injected errors as a test

Knowing every error count up front let us prove the cleaning catches them.

Reject with a reason

114 rejects are explainable row by row, not silently dropped.

Open items from the governance document
Settle one warehouse engine across Compose, DAG helpers and docs
Give the pipeline its own Snowflake loader role
Add future-date checks for attendance_date and review_date
Keep clean, rejects and logs for each run date
Add a separate department dimension
Schedule the DAG instead of a manual trigger
