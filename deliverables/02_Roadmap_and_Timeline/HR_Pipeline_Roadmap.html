Project guideline

Eight required tasks from the brief

Objective

Build an automated HR data pipeline that integrates employee datasets, improves data quality, stores structured data in a warehouse, and supports workforce reporting. HR needs consistent headcount, attendance, department and performance reports, with sensitive information protected.

Ground rules

  • Synthetic or anonymised data only. No real employee records in the repo.
  • All code goes in through a pull request that another member reviews.
  • Never edit raw files. Cleaning writes new files.
  • Stuck for more than half a day? Tell the group chat.

Data lake layout

data/
├ raw/
│ ├ employees/
│ ├ attendance/
│ └ performance/
│   └ 2026-11-07/
├ clean/
└ rejects/
  • raw: read-only sources
  • clean: validated output
  • rejects: failed rows + reason

Star schema

  • FactAttendance: employee, date, status, hours
  • FactPerformance: employee, date, score 1–5
  • DimEmployee: ID, job title, department, hire date
  • DimDepartment: name, division
  • DimDate: day, month, quarter, year

Quality rules

  • Employee ID unique and not empty
  • Status: Present, Absent, Leave or Late
  • Hours worked 0 to 24
  • Valid dates, none in the future
  • Every row points to a known employee
  • Department in the reference list

Access & privacy

  • hr_admin: everything, raw lake
  • hr_analyst: warehouse, read-only
  • report_viewer: dashboard only
  • No names, phones or addresses in reports
  • Raw files 12 months, warehouse 5 years
